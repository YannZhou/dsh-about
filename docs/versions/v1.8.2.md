## 变更说明

本版重点是让更新更可靠：dsh 本体更新改由独立后台任务完成，失败时尝试恢复旧版；页面重新打开后能够接续进度。审核中还修复了插件更新中断后无法解锁、残留锁阻塞、其他页面进度不同步和版本兼容判断的边界问题。

另外加入 Windows/macOS 的一次性迁移提示：**从下一个版本起，dsh-about 将不再支持 Windows 和 macOS，推荐使用支持自动更新的官方桌面端。** 本版保留现有三平台实现，Linux 不显示该提示。

### 一、Windows/macOS 一次性迁移提示

- Windows、macOS 用户首次打开「设置 → 关于」时显示「平台支持调整」弹窗，说明下一个版本停止支持这两个系统，并推荐官方桌面端。
- 点击「我知道了」、按 `Esc` 或点击弹窗外的遮罩均可关闭；支持键盘操作，关闭后恢复原来的焦点。
- 按**运行 dsh 的机器**判断平台，使用宿主 `/dsh-about/describe` 返回的信息，不使用浏览器的系统标识。例如：在 Windows 电脑上打开 Linux 服务器上的 dsh，不会弹出提示。
- 已展示标记保存在当前浏览器、当前站点的 `localStorage`，同一浏览器刷新或重新打开页面不会重复显示，标记不随插件版本号变化。更新弹窗打开时暂缓显示，避免两个弹窗重叠。
- 浏览器禁用存储时仍能关闭，当前页面生命周期内不重复；清除站点数据、更换浏览器或访问地址后，可能重新提示。
- Linux、未知平台以及获取系统信息失败时均不弹窗，也不写入已展示标记。

### 二、本轮审核修复的四个问题

#### 1. 插件自更新中断后一直无法再次更新

**原来的问题：** 插件自更新中断会留下“需要恢复”状态，但插件任务没有 dsh 本体的备份快照。旧恢复逻辑仍要求快照，结果既不能恢复，也不能再次更新。

**现在的处理：** 启动插件安装程序之前，先记录原 profile、依赖键和包名。恢复时单独检查包名、版本、宿主入口、浏览器入口及 patch 文件；检查浏览器脚本语法，并在独立进程中加载宿主模块依赖，确认文件与依赖可用后才解除阻塞。

损坏或缺依赖时保留阻塞并提示修复，手动重新安装后可以重试恢复。旧任务只有一个明确安装位置时自动选择，多个候选位置时使用 `--profile` 指定原位置。原宿主、安装程序或相关进程组仍在运行时拒绝恢复，恢复校验进程也记录身份；拿到锁后再次确认任务身份，避免误解锁。

这里的“插件恢复”是**检查已安装文件、确认可用后解除阻塞**，不等于回滚插件版本。dsh 本体的快照回滚仍走原来的恢复路径。

#### 2. 异常退出遗留的锁让更新永久卡住

**原来的问题：** 回收旧更新锁时也有一把保护锁；回收进程异常退出后，这把锁可能没有持有者信息，之后的更新和恢复就一直被挡住。

**现在的处理：** 普通锁和回收锁都记录进程身份，保留 20 秒创建宽限。已失效的回收锁、旧版空锁及嵌套残留锁可以安全清理；活跃持有者仍受保护。取得主锁后再次检查恢复状态。六个进程同时竞争的回归测试确认，同一时刻只有一个进程获得更新权限。

可以把它理解为“正在更新，请排队”的牌子：更新进程还在时不能拿走；进程已经退出、只剩旧牌子时，可以安全清理。

#### 3. 其他页面启动更新后，当前页面不显示进度

**原来的问题：** 空闲页面停止查询状态，因此在另一个标签页启动更新后，当前页面看不到新任务。

**现在的处理：** 空闲时每 15 秒查询，发现任务后每 1.5 秒查询；窗口重新获得焦点或恢复可见时立即同步。发现外部更新时也启用已有的白屏恢复守卫，任务结束后清除旧进度，页面卸载时移除监听器。插件恢复错误现在显示在插件更新弹窗中，避免误出现在 dsh 本体更新弹窗。

例如：在 A 标签页点击更新，B 标签页即使一直没操作，也会显示该更新的进度；切回 B 时会立即刷新状态。

#### 4. 少数版本范围被误判为兼容或不兼容

**原来的问题：** 内嵌版本范围判断对非法比较符、通配符与预发布后缀的处理，存在与标准库不一致的边界。

**现在的处理：** 拒绝 `==1.2.3`、`>==1.2.3` 等非法比较符；补齐 caret/tilde 前缀、通配符尾部、预发布和构建后缀，以及展开后版本边界的校验。例如正确处理 `^1.x.3`、`1.2.x-alpha`，降低把兼容插件误报成不兼容的可能。与本机 `node-semver 7.8.5` 对照 2,400 组，零差异，固定边界已纳入测试。

以下为本版更新、安装和卸载链路的完整调整。

## 更新与回滚

- 把快照、npm 安装、健康校验、自愈重试、失败回滚和结果落盘放入同一个独立任务。任务所需代码先复制到 `$DSH_HOME/dsh-about/jobs/`，避免安装替换正在执行的文件。
- Linux systemd 环境中，事务进程与 npm 安装分别使用独立 transient unit。npm 单元显式使用 `KillMode=control-group`；超时或派发异常时先确认安装单元停止，再恢复文件。其他环境使用独立 Node 进程与进程组，Windows 使用 `taskkill /T /F`。
- 安装任务使用文件锁实现跨宿主互斥。宿主退出后，新宿主仍能查询任务状态；后台任务意外退出会报告 `interrupted`，需要恢复时阻止再次安装。
- 回收锁也记录进程身份；异常退出遗留的普通锁、回收锁和旧版空回收锁均可安全恢复，活动持有者仍受互斥保护。
- 插件自更新在启动安装前记录原 profile。中断后由恢复命令校验已安装插件并解除阻塞；旧任务支持唯一位置推断或 `--profile` 显式选择，损坏安装不会被误判成功。
- 前端提交更新后轮询持久状态；页面重新打开、请求断开后可接续进度与结果。空闲时每 15 秒查询一次，重新获得焦点或恢复可见时立即同步其他页面的任务；活动任务仍每 1.5 秒查询。重启完成仍要求目标版本一致且宿主 nonce 改变。
- 快照复制真实包内容，链接被重新定位到备份内部，覆盖根目录链接和 pnpm 依赖环。创建新快照不会删除旧的恢复资料。
- 保留 npm 12 原生依赖白名单与一次 `--force` 重试；仅在确有脚本被拦、且当前 npm 支持时使用一次性全量脚本开关。

例如：关闭「关于」页面后，dsh 本体更新可以继续；安装新版失败时，任务会尝试恢复旧版。关机或强杀后台任务本身不会继续安装，需要按后文恢复步骤处理。

## 安装位置与重启

- 优先从正在运行的 CLI 确定 dsh 包根，结合 npm prefix 核对安装位置；备份、安装、CLI 修复和回滚使用同一位置，支持自定义 prefix 与 nvm。
- npm 优先使用当前 Node 配套的 JS 入口，避免 Windows shell 拼接和路径含空格问题。CLI 明确读取 `bin.dsh`，同时校验磁盘版本和实际版本输出，避免子串误判。
- registry、prefix、PATH、代理和自定义环境保持一致；敏感环境通过 `0600` 临时文件交给独立任务，不出现在 systemd 命令参数中，读取后删除。
- 只有启动器成功退出且看护确认初始化后才允许宿主退出。派发失败或超时会保留当前宿主并报告手动重启原因。

## 兼容性与卸载

- 扫描所有 profile，并跟随 scope、插件及 provider 的有效链接。peer provider 按 profile 和实际宿主解析。
- 内嵌 SemVer 范围匹配支持比较符组合、`||`、连字符、通配符、`^`、`~` 和 prerelease 限制，仍无运行时依赖。
- 补齐 `==1.2.3` 等非法比较符，以及 caret/tilde 通配符尾部和带 prerelease 的通配符范围边界。
- npmrc 备份以 `0600` 排他创建；已存在的普通备份收紧权限，拒绝备份路径中的符号链接。
- 卸载前先检查其他 profile、更新任务、待恢复快照和活动看护。仍被使用的共享认证、缓存、日志和任务资料会保留。Bash 与 Node 卸载入口共用同一实现，需在完整项目目录中运行。

## 故障恢复

后台任务本身被强杀或回滚失败时，先确保安装进程全部停止，再从完整项目目录运行：

```sh
node scripts/recover-update.mjs
```

非默认数据目录须设置相同的 `DSH_HOME`。本体恢复使用任务保存的原安装位置和快照，再次检查旧版 CLI；插件恢复检查已安装版本的入口及模块加载，不会回滚插件版本。插件恢复前须关闭原宿主，旧任务存在多个候选位置时追加 `--profile web`（替换为原 profile）；安装损坏时先手动重新安装再恢复。无法确认安装进程已停时拒绝恢复。
