## 变更说明

### 一、安装失败恢复旧版

更新前先保存当前 dsh 包快照。新版本安装失败时恢复快照并重新检查版本与 CLI 入口，避免更新失败后留下不可运行的半安装状态。以不存在的 `@deepseek-ai/dsh@0.2.2-rc.999999` 注入失败，实测恢复到 `0.2.2-rc.3`，`dsh --version` 正常退出。

### 二、npm 安装脱离 dsh-web cgroup

故障根因是安装 npm 子进程原先随 `dsh-web` 同属 `KillMode=control-group`，更新流程停服务时会连带终止安装进程，造成包树更新中断并可能令 CLI 入口不可执行（systemd 表现为 `203/EXEC`）。现在安装任务通过独立 systemd transient unit 执行；更新状态供控制器识别。验证覆盖真实更新执行窗口和临时 unit 清理。

### 三、CLI 入口校验与原子自愈

安装后核验 `/home/yan/.npm-global/bin/dsh` 指向的真实文件和版本。入口断链时先创建临时符号链接再原子替换。故障注入后 `dsh --version` 恢复为 `0.2.2-rc.3`。

### 四、更新期间拒绝停服

更新进行中对 AI-Glass Controller 的 `POST /api/dsh/stop` 返回 HTTP 409，并给出等待更新完成后重试的说明；更新期实测响应和控制器访问日志已记录。

### 五、插件版本兼容与联动提示

关于页执行兼容性扫描，并在存在版本不匹配时提示用户联动更新相关插件。dsh 0.2.2-rc.3 的实测 compatibility 响应为 `warnings: []`。

### 六、profile 依赖与 documentpreview 安装修复

web profile 显式声明 peer provider 后，`pnpm peers check` 退出码为 0。documentpreview 的上游 `0.2.2-rc.3` 包含 `package.json` 和 `lib/index.js`；本机共享 profile 入口此前指向全局 dsh 中残缺的旧包。将入口改指向 web profile 的完整版本并重启后，新增启动日志不再出现该导入失败。

### 七、测试与回归

插件测试 53 项全部通过；回归时 dsh-web 保持 active，3080 根路径返回 401 认证响应，`/dsh-about/compatibility` 返回 `warnings: []`。
