## 变更说明

### 一、新增：显示插件自身版本，并支持一键自更新

以前「关于」只能看 dsh 本体的版本，插件自己是不是最新得去 npm 查。这版把插件版本搬进面板：

- 新增「插件版本 vX.Y.Z」行，读的是**正在运行的这份代码**的 `package.json`，所以 `link:` 本地源码安装和 npm 安装两种形态显示都准。
- 有新版时：「插件版本」标签右上角出现小红点，设置导航里「关于」那一格右上角同步出现红点（带说明）。
- 点版本号即可一键更新：宿主执行 `dsh plugin --profile <profile> add @yannzhou/dsh-about@<版本>`（与插件市场同一条命令），装完自动重启 dsh web，页面轮询到新版就绪后自动刷新。显式指定版本号可绕开 pnpm「新版本发布未满 24 小时」的静默回退。
- 更新前会提醒「建议优先更新本插件」：装新版 DSH 后旧插件可能失效、届时无法再发起更新。
- **本地源码安装（`link:` / `file:`）拒绝自更新**并说明原因——那会把开发目录替换成 npm 包。

宿主侧新增两个路由：`GET /dsh-about/plugin`（读当前版本与安装形态，`?force=1` 强刷，5 分钟缓存，跟随当前选中源）、`POST /dsh-about/plugin-update`（与 dsh 本体更新互斥、带 CSRF 防护，目标版本必须真实存在于 npm 且比当前新，装完以磁盘上的 `version` 复核，不信退出码）。

### 二、版面重排

- 信息行序自上而下固定为 **平台 → 当前版本 → 插件版本**，删除原「项目主页」行。
- 页面右上角新增 **GitHub 图标**，点击跳转本插件项目主页。
- 「建议优先更新本插件」提示块移到「插件版本」行的正下方，并**去掉「先更新插件」按钮**，改为引导用户点击版本号（版本号旁带上下浮动的小箭头）。
- 底部「版本更新记录」的「刷新」按钮**同时强刷插件版本**——检查版本记录的时候顺带检查插件有没有新版，不必再点两次。

### 三、工程

- 新增 `.github/workflows/publish-npm.yml`：推 `v*` 标签后自动 `npm publish` 并建 GitHub Release（先校验标签与 `package.json` 版本一致、版本文档存在、JS 语法通过；该版本已发布则跳过），避免「推了 GitHub 忘了 npm」导致两边版本脱节。

## 已知限制

- **发布后 24 小时内，pnpm 默认安装会回退到旧版**（`minimumReleaseAge` 门禁，静默不报错）。自更新因为显式带了版本号，不受影响；手工安装请写全 `@yannzhou/dsh-about@1.7.0`。
- 本地源码（`link:` / `file:`）安装形态下**看不到**红点、箭头与提示块——这是设计如此：本地源码本来就比 npm 上的版本新，且不允许自更新覆盖开发目录。想看完整效果请用 npm 安装形态。
- 本插件仍然**故意不声明任何 `@deepseek-ai/*` peer 依赖**：它是管更新的插件，必须在任何 dsh 版本下都能加载。
