## 变更说明

这一版采纳了上游 PR [#2](https://github.com/YannZhou/dsh-about/pull/2)（@djs326：关于页可配置
GitHub token，含测试连接与配额回显），并把它**从跑不通做成开箱可用**：设备码授权所需的 client_id
随包内置，点两下就能拿到账号级配额；同时按用户反馈修掉两处交互问题。

### 一、在线认证开箱可用（client_id 内置）

设备码流程（取一次性码 → 在浏览器输入码 → 轮询取回 token）此前因为源码里的 client_id 是空串而
**走不通**：未配置时面板只能给出注册指引，「在线认证」实际上是一条死路。

现在内置了已注册 OAuth App 的标识符。**client_id 是可以公开的**：它本来就会出现在授权页 URL 里，
设备码流程也不需要 `client_secret`——而 GitHub 的网页授权流程**必须**带 `client_secret`，这正是
公开分发的插件不能走那条路的原因（把 secret 提交进公开仓库是高频事故，有 CVE 就是因此）。
GitHub 官方的 `github-mcp-server` 发行版同样内嵌已注册应用，属业界标准做法。

自托管 / 自测仍可用环境变量覆盖：`DSH_ABOUT_GITHUB_CLIENT_ID`。

### 二、client_id 的判定改为「显式覆盖」语义

`deviceClientId()` 原先用 `||` 回退：`DSH_ABOUT_GITHUB_CLIENT_ID=""`（空串）会被当作假值吞掉，
于是源码里一旦有默认值，「本次强制视为未配置」这个状态就再也表达不出来——自测与单元测试都失去抓手。

改为 `"DSH_ABOUT_GITHUB_CLIENT_ID" in process.env` 判定：**变量存在即以其值为准**（哪怕是空串），
不存在才用内置默认值。

### 三、点「在线认证」不再当场弹授权页

点一下入口就直接跳走太突兀。现在「在线认证」**只展开面板**，面板里有说明和「开始认证」按钮，
点了才取码并打开授权页。

> 实现要点：打开授权页仍发生在**点击手势里同步执行**；若改成「取到码之后再异步开窗」，
> 会被浏览器弹窗拦截。

### 四、未认证时提示出口 IP 的限流

认证区标题行下方新增一行红字：**未认证出口IP限60次每小时，推荐认证**（仅在确实未配置时显示，
加载中不显示，避免闪烁）。标题行原先重复的「未设置（按出口 IP 限 60 次/小时）」收敛为「未设置」，
不再相邻两行说同一件事。

口径来自 GitHub 官方文档：未认证 **60 次/小时，按来源 IP**；认证后 **5,000 次/小时，绑账号**
（该账号的 PAT 与其授权过的所有应用**共用**这一份，用户之间不互相挤占）。

### 五、测试

用例数 52 → 53，CI 三平台全绿。除了给两条「未配置」用例显式压上配置状态，还新增了一条守卫用例：
**未设环境变量时 `/dsh-about/auth` 必须报告设备码可用**。以后谁把内置的 client_id 改空，CI 立刻
变红——不会再出现「发出去的包里没有 client_id」这种事故。

## 已知限制

- **设备码仍需要人手动输一次短码**：公开分发的插件做不到零操作，这是由「网页授权流程必须带
  client_secret」决定的。
- **OAuth App 的 Device Flow 必须开启**（App 设置页的 Enable Device Flow）。未开启时 GitHub 对
  **任何** client_id 都返回 **404**——所以**不能**用 404 判断 client_id 对不对。
- **限流三条线**：未认证 60 次/小时按**出口 IP**（共享代理、机房节点很容易打满，界面会报 403）；
  认证后 5,000 次/小时按**用户**；一小时内新增 token 2,000 次按 **app**。规模上来后按官方建议换
  **GitHub App**（令牌更短期、权限细到仓库、上限可随规模增长）；注意 **OAuth App 不能迁移到组织**。
- 内置的 client_id 目前**只有源码一处**、没有运行时配置项（可用 `DSH_ABOUT_GITHUB_CLIENT_ID`
  临时覆盖）。后续可考虑升级为运行时配置或迁移到 GitHub App。
- **发布后 24 小时内，pnpm 默认安装会回退到旧版**（`minimumReleaseAge` 门禁，静默不报错）。
  自更新显式带了版本号，不受影响；手工安装请写全 `@yannzhou/dsh-about@1.8.1`。
- 本插件仍然**故意不声明任何 `@deepseek-ai/*` peer 依赖**：它是管更新的插件，必须在任何 dsh
  版本下都能加载。
